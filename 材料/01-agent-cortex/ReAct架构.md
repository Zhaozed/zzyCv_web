**ReAct架构**

Cortex 主要解决五类问题：

1. 多种入口请求如何统一接入并幂等落库。
2. 同一个用户的多条请求如何正确分流到 `CHAT / NO_MEANING / NEW / EXISTING`。
3. 任务执行中如何安全调用工具、等待结果、确认危险操作并支持打断。
4. 多窗口、多设备、多实例下如何保证输出顺序和可见性一致。
5. 当实例崩溃、租约过期、路由未定案或文本未发出时，如何自动补位和自愈。

- **系统定义**：基于 ReAct 架构构建的分布式 Agent Runtime，负责准入、路由、规划、工具编排、上下文管理和流式输出控制。
- **系统处理的主要请求类型**：
  - `REQ`：普通用户请求，是主链路入口。
  - `UI_ACTION`：界面动作，会先被转成内部 `REQ` 再进入主链路。
  - `TOOL_RESULT`：用户侧本地工具回流结果，用于闭环等待中的本地工具调用。
  - `ONLINE / OFFLINE`：前台会话在线态控制消息，只更新运行态，不进入 Router。
  - `FACE`：人脸识别事实，只更新运行态快照，不进入 Router。
- **核心功能需求**：
  - **意图与目标解析**：判断是闲聊、无意义输入、新任务还是继续旧任务。
  - **规则短路**：对高频固定表达优先走 `quick_router` 或 `quick_plan`，减少 LLM 成本和波动。
  - **任务执行**：通过 `THINK -> CALL_TOOL / ASK_USER / DONE` 循环推进复杂任务。
  - **工具调用**：支持本地工具、在线工具、危险工具确认、静默衍生工具。
  - **输出控制**：统一控制 `NOTICE / QUESTION / TOOL_CALL / TOOL_EVENT / ROUTER_RESP` 的发出时机与顺序。
  - **记忆管理**：维护短期上下文与长期偏好记忆。
- **非功能需求**：
  - 高并发下的状态一致性。
  - 输出顺序稳定，不串话、不丢收口。
  - 崩溃后的自动恢复与补发。
  - 完整的审计、回放和问题定位能力。
